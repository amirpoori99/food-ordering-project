# 📋 مستندات معماری پروژه AUT-Food Frontend

## 🏗️ ساختار کلی پروژه

```
front/
├── src/main/
│   ├── java/com/foodi/appFrontend/
│   │   ├── foodiApp.java (کلاس اصلی برنامه)
│   │   ├── models/ (مدل‌های داده)
│   │   ├── utils/ (کلاس‌های ابزاری)
│   │   └── tabs/ (کنترلرهای UI)
│   └── resources/com/foodi/appFrontend/
│       ├── view/ (فایل‌های FXML)
│       ├── css/ (استایل‌ها)
│       ├── images/ (تصاویر)
│       └── fonts/ (فونت‌ها)
├── target/ (فایل‌های کامپایل شده)
├── pom.xml (تنظیمات Maven)
└── module-info.java (تنظیمات ماژول)
```

## 📁 تحلیل فولدرها و وظایف آنها

### 1. فولدرهای اصلی

#### `front/` - ریشه پروژه فرانت‌اند
- **وظیفه**: پروژه JavaFX برای رابط کاربری برنامه AUT-Food
- **تکنولوژی**: JavaFX + Maven + Java 21
- **هدف**: ارائه رابط کاربری مدرن و کاربرپسند برای سیستم سفارش غذا

#### `front/src/` - کدهای منبع
- **وظیفه**: حاوی تمام کدهای Java و منابع برنامه
- **ساختار**: جداسازی کدها و منابع

#### `front/src/main/` - کدهای اصلی
- **وظیفه**: کدهای اصلی برنامه (غیر از تست‌ها)
- **محتوای مهم**: Java classes و resources

#### `front/src/main/java/` - کدهای Java
- **وظیفه**: تمام فایل‌های Java برنامه
- **ساختار**: پکیج‌بندی منظم بر اساس مسئولیت

#### `front/src/main/resources/` - منابع برنامه
- **وظیفه**: فایل‌های غیر Java (FXML, CSS, تصاویر)
- **محتوای مهم**: UI definitions, styles, assets

### 2. فولدرهای کد Java

#### `com/foodi/appFrontend/` - پکیج اصلی
- **وظیفه**: تمام کلاس‌های اصلی برنامه
- **ساختار**: پکیج‌بندی بر اساس الگوی MVC

#### `models/` - مدل‌های داده
- **وظیفه**: کلاس‌های POJO برای نمایش داده‌ها
- **الگوی طراحی**: Data Transfer Objects (DTOs)
- **فایل‌ها**:
  - `User.java` - مدل کاربر با نقش‌های مختلف
  - `FoodItem.java` - مدل آیتم غذا با جزئیات کامل
  - `Restaurant.java` - مدل رستوران با اطلاعات مکانی
  - `Order.java` - مدل سفارش با وضعیت‌های مختلف
  - `Transaction.java` - مدل تراکنش مالی
  - `Coupon.java` - مدل کوپن تخفیف
  - `ItemRating.java` - مدل امتیازدهی و نظرات

#### `utils/` - کلاس‌های ابزاری
- **وظیفه**: کلاس‌های کمکی و ابزاری
- **الگوی طراحی**: Utility Classes + Singleton
- **فایل‌ها**:
  - `ApiClient.java` - کلاینت HTTP برای ارتباط با سرور
  - `AuthManager.java` - مدیریت احراز هویت و توکن‌ها
  - `JsonUtil.java` - پردازش JSON و تبدیل داده‌ها

#### `tabs/` - کنترلرهای UI
- **وظیفه**: کنترلرهای مختلف رابط کاربری
- **الگوی طراحی**: MVC Controller Pattern
- **زیرفولدرها**:
  - `login/` - کنترلر ورود و احراز هویت
  - `signup/` - کنترلر ثبت‌نام و ایجاد حساب
  - `dashbord/` - کنترلرهای داشبورد بر اساس نقش

#### `tabs/dashbord/` - کنترلرهای داشبورد
- **وظیفه**: کنترلرهای مختلف داشبورد بر اساس نقش کاربر
- **الگوی طراحی**: Role-based UI Controllers
- **فایل‌ها**:
  - `BuyerDashboard.java` - داشبورد خریدار با قابلیت سفارش
  - `SellerDashboard.java` - داشبورد فروشنده با مدیریت رستوران
  - `CourierDashboard.java` - داشبورد پیک با مدیریت تحویل
  - `AdminDashboard.java` - داشبورد ادمین با مدیریت سیستم
  - `CartController.java` - کنترلر سبد خرید و مدیریت آیتم‌ها
  - `RestaurantMenuController.java` - کنترلر منوی رستوران
  - `FoodItemDetailsController.java` - کنترلر جزئیات غذا
  - `OrderDetailsController.java` - کنترلر جزئیات سفارش
  - `UserProfileController.java` - کنترلر پروفایل کاربر
  - `RatingDialogController.java` - کنترلر امتیازدهی و نظرات
  - `CouponFormController.java` - کنترلر فرم کوپن تخفیف
  - `RestaurantFormController.java` - کنترلر فرم رستوران
  - `FoodItemFormController.java` - کنترلر فرم آیتم غذا

### 3. فولدرهای منابع

#### `resources/com/foodi/appFrontend/` - منابع برنامه
- **وظیفه**: تمام فایل‌های غیر Java
- **ساختار**: سازماندهی بر اساس نوع فایل

#### `view/` - فایل‌های FXML
- **وظیفه**: تعریف رابط کاربری با XML
- **الگوی طراحی**: Declarative UI Definition
- **فایل‌ها**:
  - `login.fxml` - صفحه ورود با فرم احراز هویت
  - `signup.fxml` - صفحه ثبت‌نام با فرم‌های مختلف
  - `dashbord/` - فایل‌های FXML داشبورد

#### `view/dashbord/` - فایل‌های FXML داشبورد
- **وظیفه**: رابط کاربری داشبوردهای مختلف
- **ساختار**: جداسازی بر اساس نقش کاربر
- **فایل‌ها**: تمام فایل‌های FXML مربوط به داشبوردها

#### `css/` - استایل‌های CSS
- **وظیفه**: تعریف ظاهر و استایل برنامه
- **الگوی طراحی**: Modern UI Design
- **فایل‌ها**: `application.css` - استایل‌های اصلی برنامه

#### `images/` - تصاویر برنامه
- **وظیفه**: تصاویر پیش‌فرض و آیکون‌ها

- **فایل‌ها**:
  - `default_profile.jpg` - تصویر پیش‌فرض پروفایل کاربر
  - `default_food_item.png` - تصویر پیش‌فرض غذا
  - `default_profile.png` - تصویر پیش‌فرض پروفایل

#### `fonts/` - فونت‌های برنامه
- **وظیفه**: فونت‌های مورد استفاده در برنامه
- **ساختار**: فونت‌های قابل خوانا و مدرن
- **فایل‌ها**: `Roboto-Regular.ttf` - فونت اصلی برنامه

## 🔄 روند اجرای برنامه

### 1. شروع برنامه
```
foodiApp.java (main) → login.fxml → Login Controller
```
- **مرحله 1**: اجرای کلاس اصلی `foodiApp.java`
- **مرحله 2**: بارگذاری فایل `login.fxml`
- **مرحله 3**: ایجاد کنترلر `Login.java`

### 2. فرآیند ورود
```
Login → AuthManager → ApiClient → Backend Server
```
- **مرحله 1**: کاربر اطلاعات ورود را وارد می‌کند
- **مرحله 2**: `Login` کنترلر درخواست را پردازش می‌کند
- **مرحله 3**: `AuthManager` احراز هویت را مدیریت می‌کند
- **مرحله 4**: `ApiClient` درخواست HTTP به سرور ارسال می‌کند
- **مرحله 5**: سرور پاسخ را برمی‌گرداند

### 3. هدایت بر اساس نقش
```
Login Success → Role Check → Appropriate Dashboard
- Buyer → BuyerDashboard
- Seller → SellerDashboard  
- Courier → CourierDashboard
- Admin → AdminDashboard
```
- **مرحله 1**: پس از ورود موفق، نقش کاربر بررسی می‌شود
- **مرحله 2**: بر اساس نقش، داشبورد مناسب بارگذاری می‌شود
- **مرحله 3**: کنترلر مربوط به نقش کاربر فعال می‌شود

### 4. جریان داده
```
User Action → Controller → ApiClient → Backend → Response → UI Update
```
- **مرحله 1**: کاربر عملیاتی انجام می‌دهد (کلیک، تایپ، و...)
- **مرحله 2**: کنترلر مربوطه درخواست را پردازش می‌کند
- **مرحله 3**: `ApiClient` درخواست HTTP به سرور ارسال می‌کند
- **مرحله 4**: سرور درخواست را پردازش کرده و پاسخ می‌دهد
- **مرحله 5**: پاسخ به فرانت‌اند برمی‌گردد
- **مرحله 6**: رابط کاربری بر اساس پاسخ به‌روزرسانی می‌شود

## 📋 نقش‌های کاربری

### 1. Buyer (خریدار)
- **مشاهده رستوران‌ها و منوها**: جستجو و فیلتر کردن
- **افزودن غذا به سبد خرید**: انتخاب و افزودن آیتم‌ها
- **ثبت سفارش**: تکمیل فرآیند خرید
- **مشاهده تاریخچه سفارشات**: پیگیری سفارشات قبلی
- **امتیازدهی به سفارشات تکمیل شده**: نظردهی و امتیازدهی

### 2. Seller (فروشنده)
- **مدیریت رستوران‌ها**: ایجاد و ویرایش رستوران
- **مدیریت منوها و غذاها**: اضافه کردن و ویرایش آیتم‌ها
- **مشاهده و مدیریت سفارشات**: پیگیری سفارشات دریافتی
- **مشاهده تراکنشات**: گزارش‌گیری مالی

### 3. Courier (پیک)
- **مشاهده سفارشات قابل تحویل**: لیست سفارشات آماده
- **پذیرش سفارشات**: انتخاب سفارش برای تحویل
- **به‌روزرسانی وضعیت تحویل**: گزارش پیشرفت
- **مشاهده تاریخچه تحویل‌ها**: گزارش عملکرد

### 4. Admin (مدیر)
- **مدیریت کاربران**: مشاهده و مدیریت تمام کاربران
- **تایید فروشندگان و پیک‌ها**: بررسی و تایید درخواست‌ها
- **مدیریت کوپن‌ها**: ایجاد و مدیریت تخفیف‌ها
- **مشاهده آمار کلی**: گزارش‌گیری از سیستم

## 🔗 ارتباط با Backend

### API Endpoints
- **Authentication**: 
  - `/auth/login` - ورود کاربر
  - `/auth/register` - ثبت‌نام کاربر
  - `/auth/profile` - پروفایل کاربر

- **Restaurants**: 
  - `/restaurants` - لیست رستوران‌ها
  - `/restaurants/{id}/menu` - منوی رستوران

- **Orders**: 
  - `/orders` - مدیریت سفارش‌ها
  - `/orders/{id}` - جزئیات سفارش

- **Users**: 
  - `/users` - مدیریت کاربران
  - `/users/{id}` - جزئیات کاربر

- **Coupons**: 
  - `/coupons` - مدیریت کوپن‌ها

- **Ratings**: 
  - `/ratings` - مدیریت امتیازها و نظرات

### Data Flow
1. **User Action**: کاربر عملیاتی انجام می‌دهد (کلیک، تایپ)
2. **Controller**: کنترلر درخواست را پردازش می‌کند
3. **ApiClient**: درخواست HTTP به سرور ارسال می‌شود
4. **Backend**: سرور درخواست را پردازش می‌کند
5. **Response**: پاسخ به فرانت‌اند برمی‌گردد
6. **UI Update**: رابط کاربری بر اساس پاسخ به‌روزرسانی می‌شود

### Error Handling
- **Network Errors**: مدیریت خطاهای شبکه
- **Validation Errors**: اعتبارسنجی ورودی‌ها
- **Authentication Errors**: خطاهای احراز هویت
- **User-friendly Messages**: پیام‌های خطای مناسب
